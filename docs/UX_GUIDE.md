# UX 흐름 가이드

> `docs/UI_GUIDE.md`가 "무엇으로 만들지"(토큰·컴포넌트)를 다룬다면, 이 문서는 "어떤 순서로 사용자를 데려갈지"(유입 → 온보딩 → 전환)를 다룬다. 원칙 출처는 [Figma: UI Design Principles](https://www.figma.com/ko-kr/resource-library/ui-design-principles/) — 7가지 원칙 중 FinSight의 실제 사용자 여정에 적용되는 것만 골라 구체화했다.

## Figma의 7가지 UI 원칙 (요약)
| 원칙 | 핵심 |
|------|------|
| 계층 구조 (Hierarchy) | 크기·굵기·대비·간격으로 "먼저 봐야 할 것"을 지정 |
| 점진적 공개 (Progressive Disclosure) | 정보·기능을 단계별로 노출해 인지 부하를 줄임 |
| 일관성 (Consistency) | 동일한 패턴 반복으로 익숙함 형성 |
| 대비 (Contrast) | 색상 대비로 시선을 핵심 행동으로 유도 |
| 접근성 (Accessibility) | 대비·대체텍스트·키보드 탐색 보장 |
| 근접성 (Proximity) | 관련 요소를 물리적으로 묶어 관계·흐름을 표현 |
| 정렬 (Alignment) | 그리드로 예측 가능한 레이아웃 |

이 중 FinSight 여정 설계에서 특히 자주 쓰는 것은 **점진적 공개**(온보딩·처리 대기 단계에서 포기율을 낮춤), **계층 구조**(각 화면에서 CTA 하나만 튀게 함), **근접성**(관련 동작을 묶어 다음 단계를 명확히 함)이다.

## 전체 사용자 여정
```
랜딩(비로그인)
  → Google 로그인 (ADR-003: 로그인 없이는 업로드 불가)
  → 대시보드 첫 방문 (빈 상태, 업로드 유도)
  → CSV/PDF 업로드
  → 분석 중 (동기 처리, 스피너 — ADR-004: Haiku 파싱 → Sonnet/Opus 분류·요약)
  → 결과 대시보드 (요약 카드 → 도넛차트 → 월별 추이 → 거래 테이블)
  → [Free quota 소진 시] 블러 결과 + 업그레이드 CTA (ADR-006)
  → Polar 체크아웃 → 웹훅 반영 → Pro 대시보드
```
각 화살표가 하나의 "넘어가는 순간"이다. 아래 단계별 가이드는 이 화살표들이 끊기지 않게 만드는 데 초점을 둔다.

## 1. 랜딩 페이지 — 첫 3초에 무엇을 보여줄지
**목표**: 로그인 전환. PRD상 후기·FAQ는 MVP 제외 대상이므로, 그런 장식 없이 **계층 구조**만으로 설득해야 한다.

- 화면 상단에 헤드라인 1개 + 서브헤드 1개 + CTA 버튼 1개만 둔다. 헤드라인은 "AI가 다 해드립니다" 류의 막연한 문구 대신, "카드 명세서 올리면 이번 달 어디에 얼마 썼는지 보여드립니다"처럼 실제로 일어나는 일을 구체적으로 말한다.
- 히어로 아래로는 "인사이트를 실제로 보여주는" 섹션을 계층 구조 순서대로 이어 붙인다: ① 실제 결과 대시보드 목업(예시 데이터, `DonutChart`/`MonthlyTrendChart`/`StatTile` 재사용) → ② AI 처리 과정 인포그래픽(ADR-004의 2단계 Claude 호출 구조와 정확히 일치시키고, 실제보다 과장된 속도·진행률 표현은 금지) → ③ 카테고리 자동분류를 보여주는 아이콘 그리드. 세 섹션 모두 후기·FAQ·가격비교가 아니라 "제품이 실제로 하는 일"을 코드로 그린 시각화이며, 각 섹션에 목업/예시 데이터임을 캡션(`text-ink-subtle`)으로 명시해 실제 사용자 데이터처럼 보이지 않게 한다. 데모 GIF·자동재생 영상은 여전히 금지(정직성 원칙 및 "도구처럼 보여야 한다" 원칙과 충돌).
- CTA는 페이지 전체에서 동일한 하나의 행동("Google로 시작하기")만 존재해야 한다. 다만 스크롤 길이가 늘어난 만큼, 히어로와 페이지 최하단에 **동일 CTA를 반복 배치**하는 것은 허용한다 — 서로 다른 문구·목적의 보조 CTA(로그인/회원가입 분리 등)를 새로 만드는 것은 여전히 금지. 이는 "각 스크롤 화면(뷰포트)마다 다음 행동을 하나로 유지한다"는 계층 구조 원칙의 연장이지, 페이지 전체 CTA 인스턴스 수를 늘리라는 뜻이 아니다. 이메일 로그인 자체가 없음(ADR-003).
- `UI_GUIDE.md`의 AI 슬롭 금지 목록(그라데이션 텍스트, 글로우, "Powered by AI" 배지 등)은 랜딩에서 가장 위반하기 쉬우니 여기서 다시 확인한다. 신규로 추가되는 스크롤 리빌·카운트업 애니메이션도 `UI_GUIDE.md`의 "랜딩 전용 확장" 예산을 벗어나지 않는지 확인한다.

## 2. 로그인 — 마찰 최소화
**목표**: 이탈 없이 1클릭으로 통과.

- Google OAuth 버튼 하나만 화면에 둔다. 로딩 중 상태(리다이렉트 대기)를 버튼 자체의 비활성+스피너로 보여줘서 "눌렸는지" 불안하지 않게 한다.
- 로그인 실패/취소 시에도 랜딩으로 조용히 돌아가고, 어떤 개인정보도 요구하는 추가 폼을 넣지 않는다(이메일/비밀번호 가입 없음).

## 3. 대시보드 빈 상태 — 다음 행동을 한 곳으로 모으기
**목표**: 로그인 직후 "뭘 해야 하지?"라는 공백이 생기지 않게 한다.

- 데이터가 없을 때 빈 테이블/빈 차트를 보여주지 않는다. 대신 업로드 위젯 하나를 화면 중심(좌측 정렬 원칙 안에서 가장 눈에 띄는 위치)에 두고, 아래에 "CSV/PDF 어디서 받나요" 같은 짧은 안내만 둔다.
- 이 시점에는 카드사별 CSV/PDF 포맷 차이, 2,000행/용량 제한 같은 세부 제약을 미리 나열하지 않는다(점진적 공개) — 실제로 문제가 생겼을 때(에러 상태)만 구체적으로 설명한다.

## 4. CSV/PDF 업로드 — 제약은 필요할 때만 보여준다
**목표**: 업로드 시도 자체의 진입 장벽을 낮추되, 실패했을 때는 원인을 명확히 알려준다.

- 기본 상태: 드래그앤드롭 영역 + "CSV 또는 PDF 파일 선택" 텍스트 버튼. 지원 인코딩(EUC-KR/CP949 자동 대응)이나 용량 제한(CSV 2MB/PDF 5MB)은 작은 캡션(`text-ink-subtle`)으로 한 줄만 상시 노출.
- 에러 상태(용량 초과, 2,000행 초과, 인코딩 실패, PDF 텍스트 추출 실패 등)에서만 구체적 원인과 다음 행동("최근 3개월만 내려받아 다시 시도")을 제시한다 — 이것이 점진적 공개: 잘못됐을 때만 자세히.
- 업로드 버튼(Primary CTA)과 파일 선택 영역을 근접 배치해 "여기서 다음 단계로 넘어간다"는 흐름을 시각적으로 묶는다.

## 5. 분석 중 (동기 처리) — 대기를 견딜 수 있게
**목표**: 백그라운드 큐 없이 동기로 처리하는 구조(ARCHITECTURE.md)라 체감 대기시간이 김. 이 구간에서 이탈하지 않게 하는 것이 이 앱에서 가장 중요한 UX 문제 중 하나.

- 단일 스피너 대신 **단계 라벨**을 순차 표시한다: "파일 읽는 중" → "거래 내역 인식 중" → "카테고리 분류·요약 작성 중". 실제 두 단계 Claude 호출(ADR-004: Haiku 파싱 → Sonnet/Opus 분류)과 일치시켜 거짓 진행률을 만들지 않는다.
- 가짜 퍼센트 진행바(예측 불가능한 값을 숫자로 확정해 보여주는 것)는 쓰지 않는다 — "도구처럼 보여야 한다"는 원칙과 정직성 모두에 위배. 라벨 전환 + 인디케이터 애니메이션(`UI_GUIDE.md`의 crossfade 200ms 톤 유지)이면 충분하다.
- 이 화면을 벗어나거나 새로고침하면 무엇이 사라지는지(재시도 필요 여부)를 짧게 안내한다.

## 6. 결과 대시보드 — 정보 위계
**목표**: "이번 달 어디에 얼마 썼는지"를 3초 안에 파악하게 한다(PRD 핵심 가치).

- 시선 순서를 강제한다: **자연어 요약 문장**("이번 달 식비 42만원, 전체의 31%…") → **요약 카드(StatTile)** → **도넛차트** → **월별 추이** → **거래 테이블**. 테이블이 가장 아래인 이유는 원시 데이터(디테일)이지 결론이 아니기 때문 — 계층 구조 원칙.
- 카드/차트/테이블은 근접성으로 관련 있는 것끼리 묶는다: 예를 들어 도넛차트와 "카테고리별 지출" 요약 카드는 같은 섹션(같은 카드 컨테이너 또는 인접 배치)에 둔다.
- 카테고리 수동 수정은 MVP 범위 밖(읽기 전용) — 편집 가능한 것처럼 보이는 hover 스타일(밑줄, 연필 아이콘 등)을 우발적으로 넣지 않는다.

## 7. Quota 소진 → 페이월 — 조작 없이 전환시키기
**목표**: Free 사용자가 한계를 명확히 이해하고, 조급함을 강요하지 않으면서 업그레이드하게 한다(ADR-006).

- 분석은 실제로 실행하고 결과를 **블러 처리**해서 "내용이 있다"는 것 자체를 보여준다 — 완전히 숨기는 것보다 점진적 공개에 더 가깝고, 무엇을 얻는지 감을 준다.
- 블러 위에 뜨는 업그레이드 CTA는 계층 구조상 이 화면에서 유일하게 튀는 요소여야 한다(앰버 Primary 버튼, 나머지는 무채색).
- 카운트다운 타이머, "지금 아니면 놓칩니다" 류의 인위적 긴박감(다크 패턴)은 쓰지 않는다 — quota는 월 단위로 리셋되는 사실을 그대로 전달한다("이번 달 무료 업로드 3회를 모두 사용했어요. Pro로 무제한 이용하기" 정도의 담백한 문구).
- Free/Pro 기능 차이는 "무제한 업로드 + 히스토리 보관" 한 줄로 충분 — 다중 티어 비교표를 만들지 않는다(단일 Pro 티어).

## 8. 체크아웃 → Pro 전환
**목표**: Polar로의 이탈(리다이렉트)이 자연스럽게 느껴지게, 돌아왔을 때 상태가 즉시 반영된 것처럼 보이게.

- 업그레이드 버튼 클릭 → Polar 체크아웃 이동 사이에 "결제 페이지로 이동합니다" 같은 중간 확인 모달을 넣지 않는다(불필요한 단계 추가는 점진적 공개가 아니라 마찰).
- 결제 후 대시보드로 복귀했을 때 웹훅 반영 지연이 있을 수 있음(ARCHITECTURE.md: `checkout_pending`은 DB 미저장, UI 로컬 상태로만 "결제 확인 중" 표시) — 이 경우 블러를 즉시 풀지 말고 짧은 "결제 확인 중" 상태를 보여준 뒤 반영한다. 아무 표시 없이 그대로면 사용자가 결제가 실패했다고 오해한다.

## 단계 전환 체크리스트
새 화면/플로우를 만들 때마다 확인:
- [ ] 이 화면에서 Primary CTA는 하나뿐인가 (계층 구조)
- [ ] 지금 당장 필요 없는 정보/설정을 미리 다 보여주고 있지 않은가 (점진적 공개)
- [ ] 관련 동작(선택→확인, 업로드→분석 등)이 시각적으로 붙어 있는가 (근접성)
- [ ] 대기/에러 상태에서 사용자가 "지금 무슨 일이 일어나는지" 알 수 있는가
- [ ] `UI_GUIDE.md`의 AI 슬롭 금지 목록과 충돌하지 않는가
